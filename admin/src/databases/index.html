PUID (From Snowflake ID)

PUID (Pimous Unique Identifier) is a unique ID format designed to be used in all databases of Pimous Dev. without any conflict. It is based on Snowflake ID and inspired from PRUID and EVUID.

To generate those, Pimous Dev. gives a PostgreSQL function backed by a table which takes a table identifier. This latter is often halved in a schema part, preferably given by a constant, and a table part.

Definition

6 48 Table ID - last 4 bits Reserved (6 bits) Sequence Number - 6 bits
  1. Padding (1 bit): Some languages doesn't support 64 bits unsigned numbers (8 bytes), like Java (to some extent) or PHP. In order to avoid unexpected behaviors, this 1 bit padding ensures that we remain within the positive range of 64 bits signed numbers while keeping unsigned identifiers.
  2. Milliseconds from Unix epoch (43 bits): Identifier exact creation time to the nearest millisecond, based on the Unix epoch; With 43 bits, we should not be worried until the 26th September 2248, giving us 224 years.
  3. Table identifier (8 bits): A number to restrict identifiers to a defined database table, usually divided into two parts representing the schema and the table. Assignations section defines ranges affected to each Pimous Dev. applications.
  4. Reserved for future use (6 bits) (Could be used to extend Table identifier or as a worker id);
  5. Sequence number (6 bits): A number to distinguish multiple identifiers created in the same milliseconds; Each creation, a counter is incremented and reset on the next millisecond. We choosen a maximum of 64 identifiers (2^5) as PostgreSQL doesn't seem to be able to generate more with the current implementation.
